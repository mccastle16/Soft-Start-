Design system

Soft Focus

A calm, rose-toned system for interfaces that encourage rather than pressure. Every token below exists to make progress feel gentle: warm neutrals instead of stark white, soft depth instead of hard lines, and language that celebrates what's done — never what's missing.

Cozy Encouraging Never urgent

01 — Foundations

Principles

Three rules resolve every design debate before it starts.

Soft over sharp

Depth comes from tinted shadows and layered surfaces, never from borders or outlines. Corners are generous everywhere.

Calm over urgent

No reds, no badges shouting counts, no countdown timers. Attention is drawn with warmth (apricot), not alarm.

Done over due

Progress always shows what the user has accomplished. Empty states invite; they never scold. Streaks pause — they don't break.

02 — Color

Palette

Rose-led with warm neutrals. Text is a rose-brown ink (#453A3E) rather than black — softer on the eye, still 10.9:1 contrast on the canvas. There is deliberately no red: "attention" is apricot, and completion is sage.

Usage ratio

Roughly 70% neutrals (porcelain + surface), 20% blush tones, 10% rose accent. Sage and apricot appear only as small tags, dots, and fills — never as large areas.

05 — Radius & depth

Corners and shadows

Radii scale with element size — never one value everywhere. Shadows are rose-tinted (shadow color #B25F76 at low alpha) so depth feels warm instead of gray, and they replace borders entirely.

--r-sm · 10px
inputs, chips
--r-md · 16px

--r-lg · 24px

--r-pill
tags, progress

Rest

--shadow-rest — a tight 1px contact shadow plus a wide, faint rose bloom.

Lifted

--shadow-lift — used on hover with a 2px rise. Elevation is the hover language; color changes are secondary.

06 — Buttons

Buttons

Three weights, one shape family. Labels say exactly what happens — "Save changes", not "Submit". Minimum touch target 44px. One primary button per view.

08 — Tags & inputs

Tags, badges, and fields

Tags are always pills with tinted fills. Counts and statuses use calm wording — a tag says "2 rescheduled", never "2 overdue!". Inputs are quiet at rest and glow softly on focus.

Skin treatment Completed Rescheduled Optional

Focus state: rose border + 4px soft halo. Error state reuses apricot with helpful copy ("Add a date so we can save this") — never bare red text.

09 — Icons & illustration

Icons and illustration

Icons: rounded-terminal line icons (Lucide or similar) at 1.75px stroke, 24px grid, sitting in blush tiles when used as category anchors. Illustrations: soft radial color fields — dawn light, not clipart. No hard outlines, no faces, no literal metaphors.

1.75px stroke, round caps, blush tiles at --r-md. One icon per card header maximum — icons anchor, they don't decorate.

Illustration style: layered radial gradients in petal, rose, and a whisper of sage on porcelain. Use for headers, empty states, and session screens.

10 — Signature

Gentle progress

The system's one signature idea: progress is always additive. Fills grow from petal to rose like light warming; nothing drains, flashes, or counts down. The copy rules below are design tokens as much as any hex value.

Only 12% complete → You've started — the first step is done

11 — Motion

Animation

Motion is calm and singular: one orchestrated moment per screen (usually the progress fill or a soft page-load fade), plus quiet hover micro-interactions. Nothing bounces, pulses, or loops.

TokenValueUse
--t-fast160msColor/background changes, presses
--t-med260msHover lifts, shadow transitions
--t-slow420msProgress fills, panel reveals
--easecubic-bezier(.25,.6,.3,1)Everything — a soft decelerating glide

Rules: transforms and opacity only (no layout animation); hover = −2px lift + shadow soften; press = scale(.98); all motion collapses under prefers-reduced-motion. Never animate to demand attention — no shaking fields, no pulsing badges.

13 — Guidelines

Component guidelines

Quick-reference rules for building new screens without drifting from the system.

Do

  • Derive every color, size, and duration from the tokens
  • Use whitespace before adding dividers; dividers before borders; borders never for depth
  • Give every list an inviting empty state ("Nothing planned yet — add something small")
  • Keep one primary action and one signature moment per screen
  • Write buttons as verbs and outcomes in sentence case

Don't

  • Use red, exclamation marks, or countdowns anywhere
  • Show negative counts ("3 missed") — always frame as progress made
  • Stack shadows on nested cards — nest with blush tints instead
  • Add icons or emoji to every header — one anchor icon maximum
  • Animate more than one orchestrated moment per screen
